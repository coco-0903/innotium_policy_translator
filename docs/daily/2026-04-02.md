## 중간점검에서 제기된 의문 & 판단

### 의문 1: 에이전트(엔드포인트) 로그 분석
- **문제**: PA는 매니저 서버에 붙어있어 엔드포인트 로그(`C:\ProgramData\Innotium\{제품}\logs`) 접근 불가
- **판단**: 해결 가능. 수동 업로드 방식으로 즉시 구현 가능
- **결론**: 파일 업로드 → AI 분석 기능 추가 (Phase 3-2)

### 의문 2: 정책별 세세한 동작 로직 학습
- **문제**: 제어스위트 클립보드 전역/프로세스별 설정 같은 복잡한 로직을 AI가 모름
- **판단**: AI가 알아서 학습하는 건 불가능. 지식을 사람이 넣어줘야 함
- **결론**: POLICY_KNOWLEDGE를 Level 2(동작 로직)로 확장 + 매뉴얼 RAG 도입

### 의문 3: 정책 적용 후 에이전트 동작 학습
- **문제**: 설정 → 에이전트 행동 매핑을 어떻게 가르치나
- **판단**: 매뉴얼 + 기술지원 경험 축적으로 부분적 커버 가능. 100%는 비현실적
- **결론**: Few-Shot 피드백 루프 적극 활용 + 실사용 데이터 축적

### 서버 아키텍처 학습 완료

- nginx(40000) → Tomcat(8101) → MariaDB(43306) + Redis(46379) 구조 파악

## v4.0 방향성 결정

### 핵심 변경: 메인 페이지를 챗봇으로 전환

**Before (v3.6)**
```
메인 = JSON 입력 → 번역/시뮬/진단 결과
탭 = DB조회, 로그분석, 대시보드
```

**After (v4.0)**
```
메인 = 자연어 챗봇 (신입이 뭐든 물어볼 수 있음)
사이드바 = 대시보드, DB 조회, 파일 분석(기존 기능), 분석 이력
```

### 기획 의도 재확인
- **원래 목적**: 신입이 복잡한 제품을 자연어로 질문하며 학습할 수 있는 도구
- **추가된 목적**: 실무 엔지니어의 정책 분석/로그 분석/기술지원 보조
- **양립 가능**: 챗봇(신입용) + 전문 도구(실무용)을 하나의 앱에서

### 기술 결정: AI 에이전트 프레임워크 불필요
- LangChain, CrewAI 같은 에이전트 프레임워크 도입 **안 함**
- Claude API의 `tool_use` (함수 호출) 기능만으로 충분
- 이유: 단일 턴에서 DB 조회 → 분석 → 답변이면 끝. 멀티스텝 자율 추론 시나리오 없음
- 복잡도 낮추고 유지보수 가능한 구조 유지

### tool_use 동작 방식
```
사용자: "SecureZone USB 정책이 뭐야?"
  → Claude API가 판단: DB 조회 필요
  → tool_call: query_policies(product="securezone")
  → tool_result: [정책 데이터]
  → Claude가 POLICY_KNOWLEDGE + 데이터 기반 답변 생성
  → 사용자에게 자연어 답변 반환
```
읽기 전용(SELECT)만 허용. INSERT/UPDATE/DELETE 절대 불가.
