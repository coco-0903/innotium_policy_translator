## 트러블슈팅

### 1. API 키 발급 후 계속 `credit balance too low` 오류
**현상:** 크레딧 $5 충전 후에도 API 호출 시 400 오류
**원인:** 처음 발급한 API 키가 크레딧 반영 전 상태로 캐싱된 것으로 추정
**해결:** 기존 키 삭제 → 새 키 재발급 → `.env` 교체 → 즉시 정상 동작
**교훈:** API 키는 크레딧 충전 **후** 발급할 것. 안 되면 키 재발급이 가장 빠른 해결책

### 2. 챗봇 분석 버튼 클릭 시 `Unexpected token '<'` 오류 (반응 없음처럼 보임)
**현상:** 버튼 클릭 후 잠시 뒤 HTML 파싱 오류
**원인 1 (최초):** Gunicorn 워커 타임아웃(기본 30초) — Claude API 응답 대기 중 워커 강제 종료 → 500 반환 → Nginx HTML 에러페이지
**원인 2 (로그 분석):** Nginx `proxy_read_timeout 120s` 초과
**해결:**
```
# Gunicorn 타임아웃 증가 (/etc/systemd/system/policy-analyzer.service)
--timeout 180

# Nginx 타임아웃 증가 (/etc/nginx/conf.d/policy-analyzer.conf)
proxy_read_timeout 180s;
```
**교훈:** Claude API는 tool_use 루프 포함 시 60~90초 걸릴 수 있음. Gunicorn + Nginx 타임아웃은 항상 Claude timeout보다 여유있게 설정

### 3. Rate Limit 429 오류 — 입력 토큰 초과
**현상:** 챗봇에서 정책 질문 시 `rate_limit_error` (30,000 토큰/분 초과)
**원인:** POLICY_KNOWLEDGE(~15,000 토큰)가 매 챗봇 요청마다 포함되어 Tier 1 Sonnet 한도(30K/분) 초과
**해결:** 챗봇·로그분석을 Haiku(50K/분 한도)로 분리, Sonnet은 번역·진단·분석 전용 유지
**교훈:** POLICY_KNOWLEDGE가 커질수록 토큰 소비 급증. 챗봇처럼 빈번한 호출은 Haiku 사용 필수

### 4. 서버 `git pull` 실패 — 로컬 변경사항 충돌
**현상:** 서버에서 `git pull` 시 "로컬 변경사항 덮어씀" 오류
**원인:** 서버에 직접 수정된 파일들 + 추적되지 않는 `rag.py` 존재
**해결:**
```bash
git stash          # 추적 파일 임시 저장
mv rag.py rag.py.server_bak  # 미추적 파일 이동
git pull origin claude/nervous-northcutt
```
**교훈:** 서버에서 직접 파일 수정 금지. 항상 워크트리에서 수정 → commit → push → 서버 pull 순서 유지

### 5. 챗봇이 빈 배열 필드를 "기능 없음"으로 잘못 해석
**현상:** 제어스위트 프로세스 제어 항목이 있는데 "없다"고 답변
**원인:** DB에서 `controlSuiteProcessList=[]`(빈 배열) 반환 시, AI가 "해당 기능이 존재하지 않음"으로 판단
**해결:** CHAT_SYSTEM_PROMPT에 명시적 지시 추가
```
빈 배열([])이나 null = 등록된 항목 없음 (기능은 존재함)
→ search_knowledge로 설정 방법 안내하라
```
**교훈:** AI는 DB 데이터 구조를 기능 존재 여부로 오해할 수 있음. 빈 값 처리 지침을 프롬프트에 명시해야 함

### Phase 3-5 추가: TRANSLATE_PROMPT 매뉴얼 스타일 재작성
**배경:** 번역 결과물이 JSON 필드명을 그대로 나열하는 수준에 머물러, 신입 엔지니어가 읽기 어려웠음.
시큐어존 관리자 매뉴얼(`260417_시큐어존 관리자 메뉴얼 .docx`)을 참고하여 출력 형식 전면 개선.

**변경 내용:**
- 출력 구조: `[설정] > App Setting > [제품명] > 섹션명` 경로 헤더 + 설정별 한 문장 자연어 설명
- 각 설정 형식: `**UI 명칭**: **현재 값(의미어)** — 동작 설명.`
- 필드→UI명칭 매핑 테이블: 6개 제품 전체 주요 필드 포함
  - `usbControlAuth` → "휴대용 디바이스 권한 (0=미사용/1=읽기전용/2=완전차단)"
  - `isClipboardRestrict` → "클립보드 공유제한"
  - `behaviorDetectLevelType` → "행위기반 탐지 민감도 (LOW/MEDIUM/HIGH + 수치)"
  - 등 50개 이상 매핑
- 위험 설정 ⚠️ 표시 규칙 명시
- 예시 출력 포함 (시큐어존 에이전트 정책 완성 예시)
- 보안 수준 요약 테이블 형식 표준화

**기대 효과:** 번역 결과가 매뉴얼처럼 읽히므로 신입도 즉시 이해 가능.
